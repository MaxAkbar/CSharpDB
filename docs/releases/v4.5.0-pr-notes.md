## Summary

Prepare version4.5.0 on top of v4.4.0. This release adds persisted logical SQL
type semantics while retaining CSharpDB's compact carrier and page architecture
and compatibility views for existing data.

The release formalizes 25 logical SQL type kinds plus generated `ROWVERSION`.
`INTEGER`/`INT` is now signed 32-bit and checked throughout assignment,
conversion, arithmetic, identity, aggregate, index, and rewrite paths, while
`BIGINT` remains signed 64-bit. `BOOLEAN`, `BOOL`, and bare `BIT` are logical
Booleans; `BIT(n)` and `BIT VARYING` remain bit-string types. Exact decimal,
character and binary facets, UUID, temporal and interval types, JSON, XML, and
their aliases now retain declared type metadata across schema serialization and
typed APIs.

Bare `TIMESTAMP` now aliases `ROWVERSION`; temporal timestamp declarations use
`DATETIME2` or `DATETIMEOFFSET`. Rowversion values are generated from a
persisted database-wide allocator and advance for inserts and every successful
update, including no-op, raw-SQL, and trigger-issued updates. Allocation is
covered by transaction rollback, WAL recovery, checkpointing, database reopen,
and concurrent writes.

Logical type metadata and values are carried consistently through the direct
engine, ADO.NET, EF Core, HTTP, gRPC, native, Node, Admin, CLI, import/export,
schema comparison, MCP, and migration tooling. The release adds the versioned
4.5 migration capability catalog and preserves logical target declarations in
migration plans and retained artifacts.

`XML_EXISTS`/`XMLEXISTS` and `XML_VALUE` add bounded XPath 1.0 queries over XML
values, including optional JSON namespace-prefix mappings, NULL propagation,
deterministic metadata, singular-value enforcement, and secure parsing that
rejects DTDs and external entities.

Public documentation now contains the complete datatype catalog, aliases,
facets, CLR mappings, physical carriers, compatibility rules, and
provider-specific behavior. Regression coverage requires every logical type,
accepted alias, and the special rowversion declaration to remain represented in
the public reference.

## Notes for Reviewers

- This release intentionally changes public SQL semantics: `INTEGER`/`INT` is
  32-bit, bare `BIT` is Boolean, and bare `TIMESTAMP` is rowversion. Use
  `BIGINT`, `BIT(n)`, and `DATETIME2` respectively where those meanings are
  required.
- Metadata version 11 records the final semantics without redesigning existing
  database pages. Exact `DECIMAL` adds its dedicated carrier and payload;
  existing physical values retain their compatibility view.
- Descriptor-less integer columns from older databases remain `BIGINT`.
  Preview metadata-version-10 and archive-v7 `INTEGER` declarations are exposed
  as `BIGINT` so existing 64-bit values are not silently narrowed.
- Legacy per-row rowversion values are regenerated on upgrade, intentionally
  invalidating outstanding concurrency tokens. New tokens are opaque equality
  values backed by a durable database-wide allocator.
- `ROWVERSION` is limited to one generated, nonnullable column per table and
  cannot be assigned, defaulted, collated, used as identity, or included in
  keys, foreign keys, or indexes. Standalone add/alter rowversion migrations
  remain unsupported.
- Exact `DECIMAL` is the default 4.5 mapping. Existing EF properties explicitly
  configured with `.HasColumnType("INTEGER")` retain the legacy scaled-integer
  decimal mapping.
- XPath support is the bounded function-style surface documented for
  `XML_EXISTS` and `XML_VALUE`. Standard `XMLEXISTS(... PASSING ...)`,
  `XML_TABLE`, and XML path indexes are not included.
- Review the logical type contract together across parsing, execution,
  persistence, typed transports, providers, migration artifacts, and
  documentation; those surfaces are expected to expose the same canonical
  declaration.
