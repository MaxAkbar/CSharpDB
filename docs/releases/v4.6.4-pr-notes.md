## Summary

Add Studio tools for finding database definitions, assessing dependencies,
documenting schemas, and generating repeatable test data. This PR covers the
`version4.6.4` changes since v4.6.3.

- **SQL Search and Dependency Explorer:** search saved definitions, follow
  incoming and outgoing references, inspect a dependency graph, and assess
  column changes. Share findings with Data Modeler and distinguish database
  references, diagram membership, proposed changes, and archive relationships.
- **Database Documenter:** create a searchable data dictionary with descriptions
  stored in the database, revision and definition conflict checks, and complete
  HTML or Markdown exports. Support direct, HTTP, and gRPC connections and
  consecutive exports in the Windows desktop host.
- **Test Data Generator:** configure and reuse profiles, preview typed synthetic
  data, resolve supported parent/child relationships, and append in one
  transaction. Share deterministic generation and schema inference with the
  developer DataGen CLI; revalidate schema and keys before writing and report
  cancellation, rollback, and uncertain commit outcomes explicitly.
- **Fixes and documentation:** preserve comments, literals, and quoted identifiers
  during SQL parameter binding; stabilize unrelated Data Modeler connectors;
  inspect archive definitions without scanning row payloads; and update feature
  guides, website examples, shared accessibility, and documentation guardrails.

Release packaging and version preparation remain outstanding; the current
branch is not yet a qualified v4.6.4 release candidate.

Behavior and compatibility to review:

- No database file-format revision is introduced. The first description save
  creates the internal `__documentation_annotations` table; inspection and
  exports do not create it. Description saves check revisions and definitions,
  and changed or unmatched annotations remain visible as review diagnostics.
- Definition inspection does not execute saved SQL or C# modules. Dependency
  and impact results are advisory, with unresolved and dynamic references
  disclosed. Archive inspection reads metadata; it does not validate row or
  physical-index payload integrity.
- Search and documentation support direct, HTTP, and gRPC connections scoped
  to the selected database or route. Older servers may return partial metadata;
  documentation editing requires the advertised documentation capability.
- Studio generation currently supports one direct database, including direct
  hybrid incremental-durable mode. Remote/routed/sharded targets, collections,
  replace/truncate operations, generated cycles, INSERT-trigger tables,
  rowversion keys, and unsupported types or preflight expressions are blocked.
- The hardened DataGen evaluator intentionally changes legacy generated output.
  Repeatability depends on the profile, seed, reference date, generator/provider
  version, schema identities, and existing key state; an old seed alone is not
  sufficient to reproduce earlier output bytes.
- `CSharpDB.DataGeneration` remains a project-reference dependency of Studio
  and the developer CLI, with `IsPackable=false`; it is not a new standalone
  NuGet package or an addition to the umbrella package.
