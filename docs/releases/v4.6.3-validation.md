# v4.6.3 Local Release Validation

## Scope

Validation performed on 2026-09-04 for the `version4.6.3` preparation.
The published comparison baseline is v4.6.2
(`e1c7ace998cf543f8f36af727abdd0024794a24a`); implementation HEAD is
`95e5b136`. The release-version changes and test corrections are an uncommitted
overlay on that HEAD.

Tests run in separate disposable Windows and WSL checkouts, not against the
user's demo databases. Source hashes, patches, command output, and TRX reports
are retained outside the working repository. No release workflow was changed
or dispatched, and no tag, package, or release was published.

This is **local preflight evidence**, not a replacement for the clean-commit,
three-platform release qualification or the existing tag-last publishing gates.

## Corrections Found During Preflight

- The download-page test expected the old checksum `<code>` markup. It now
  asserts the actual migration-checksum download link.
- Migration preview, catalog, plan, cursor, and validation fingerprints include
  the target version. Published golden files and historical capability catalogs
  remain unchanged. Compatibility tests explicitly retain their original
  target identity; current-target checks continue to exercise 4.6.3.
- The synthetic inspector only accepts the current target, so historical
  fingerprint tests obtain the fixture through that supported entry point,
  then bind the test catalog and planner to the retained 4.6.2 capabilities.
- The inherited Windows command path exceeded `cmd.exe`'s length limit, causing
  fake release-script tools to fail to locate PowerShell. The rerun changes only
  the validation process environment, not production scripts or machine settings.
- One Linux release-runner simulation exceeded its five-minute test timeout in
  the initial run. The complete Daemon suite passed on both platforms with the
  shorter process-local command path; no timeout or performance gate was relaxed.

No production schema, storage, or modeler logic was changed during this release
preparation. The production changes here are the 4.6.3 version/default and the
matching migration capability resource.

## Deliberately Unrun Checks

- NativeAOT library publication, exported-symbol checks, and the native/trim
  smoke executable: left to CI at the user's request.
- macOS functional qualification: WSL covers Linux, not macOS.
- The hosted balanced previous-release performance comparison and complete
  release bundle/installer gates.
- Four opt-in live-provider fixtures: two Access checks and one least-privilege
  metadata check each for SQL Server and MySQL. No fixture connections or live
  credentials were supplied. Offline provider and isolation checks are separate.
- Linux additionally skips `AccessWorkerRunnerTests.ProviderFailureUsesOnlyStableProtocolState`
  because the Access worker is intentionally Windows-only. That test passed on
  Windows.
- A fresh manual browser/device/theme walkthrough was not performed in this
  release-preparation pass; automated Admin and JavaScript suites were executed.
